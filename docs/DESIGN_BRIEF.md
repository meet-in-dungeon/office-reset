# 디자이너용 정보 (DESIGN_BRIEF)

> 디자인을 맡은 사람(또는 AI)이 작업 전에 알아야 할 서비스 정보, 화면 구성, 기술 제약, 납품 형식이다.
> 기준 시점: 2026-11-24. 기능과 구조는 `main`과 팀원 브랜치 코드를 읽어 정리했다.
> **"확정"은 팀이 정한 내용이고, "미정"은 임의로 정하지 말고 임시 값으로 두어야 한다.**

## 1. 서비스

- **한 줄:** 호흡과 스트레칭을 결합해 일상 속 회복 습관을 돕는 웹 서비스.
- **서비스 이름:** 미정. 화면에는 임시 이름 "하루 회복 루틴"이 들어 있다.
- **사용자:** 30~50대 사무직. 오래 앉아 일하고 목·어깨·허리가 불편하지만 스트레칭을 못 하는 사람. (확정)
- **사용 상황:** 사무실, 업무 중, 앉은 자세. **소리는 기본 꺼짐**(사무실을 고려)이라 소리 없이도 이해되어야 한다. (확정)
- **형태:** 웹. **모바일 우선**, PC에서는 가운데에 좁은 화면으로 보여준다. (확정)
- **핵심 흐름:** 정해진 시각(평일)에 알림 → 스트레칭 3동작(각 5초) → (하루 마지막 루틴이면 호흡 5회) → 완료 화면에서 배지 → 기록·통계.
- **발표:** 11/26(목) 14:30 온라인 발표. 시연은 알림 → 스트레칭 → 배지 흐름이 중심이다.

## 2. 디자인 방향 (팀장이 정함)

- **콘셉트:** 세련된 UI와 적당한 B급 감성의 조화. 깔끔한 웰니스 서비스 느낌에 귀엽고 재미있되 유치하거나 조잡하지 않게.
- **분위기 참고:** 연한 라벤더·크림·민트 계열, 짙은 네이비 글자, 옐로우/라임 강조 버튼, 둥근 카드와 버튼, 가독성 높은 글자, 만화풍 말풍선·스티커, 과하지 않은 그림자.
- **B급 감성은 특정 요소에만 쓴다.** 앱 전체가 B급이면 안 된다. 기본 화면은 차분하게 둔다.
  - 쓰는 곳: 빡침 버튼, 배지와 보상, 루틴 완료 화면, 캐릭터의 반응, 버튼 클릭 인터랙션, 직장인 공감 문구
- **시안 이미지(`세련된 캐릭터 리셋 앱 시안`)는 무드 레퍼런스다.** 그 안의 화면 구성, 메뉴, 기능, 문구를 그대로 구현하지 않는다. (하단 메뉴, 연속 일수, 퀘스트 목록 등은 우리 기능이 아니다.)
- **문구는 임시다.** 나중에 팀이 쓴다. 디자이너가 새 문구를 만들면 "임시"로 표시한다.
- **합의되지 않은 기능을 추가하지 않는다.** 화면과 동작은 아래 3번의 구성이 기준이다.

## 3. 화면 구성 (실제 코드 기준)

모든 화면은 `Screen`(제목 줄 + 본문) 틀 안에 있다. 주소는 `#` 뒤를 쓴다. (예: `https://사이트/#/stretch`)

### 3-1. 온보딩 `#/onboarding` (처음 접속하면 여기)
제목 "하루 회복 루틴" → 소개 한 줄 → 카드 4장: ① 이렇게 쓰세요(번호 3줄) ② 언제 알려 드릴까요?(출근·퇴근 시각, 점심시간 체크와 시각, 알림 주기 선택, 평일 알림 횟수와 시각 안내) ③ 알림을 받아 볼까요?(브라우저 알림 허용 버튼과 상태 문구) ④ 주의해 주세요 → 큰 "시작하기" 버튼.

### 3-2. 메인 `#/`
- 제목 "오늘의 회복", **오른쪽 위에 원형 빡침 버튼**
- 타이머 카드: "다음 알림 HH:MM까지" + 큰 남은 시간(`mm:ss`), "알림 받기" 체크박스. (알림이 꺼짐/오늘 끝남/주말에는 문구가 바뀐다)
- 큰 "스트레칭 시작" 버튼, 보조 "기록·통계 보기" 버튼
- 설정 카드: 출근·퇴근, 점심, 알림 주기, 알림 허용, "소리 켜기" 체크

### 3-3. 스트레칭 `#/stretch` (알림을 누르면 `#/stretch?from=notification`)
세 가지 단계가 있다.
1. **시작 단계**(알림으로 들어왔을 때만): 큰 "시작" 버튼 + 주의 문구
2. **동작 단계**(3번 반복): "1 / 3 · 허리" 진행, 동작 이름, **영상 자리(16:9)**, 번호 있는 설명 3줄, **5초 카운트 숫자**, 주의사항 목록, 공통 주의 문구, **"다음" 버튼**(카운트가 끝나야 눌림). 마지막 동작에서는 "마치기".
3. **호흡 단계**(하루의 마지막 루틴에만): 제목 "호흡", "n / 5" 진행, 안내 문구("4초간 들이쉬세요" / "편안하게 내쉬세요"), 큰 카운트 숫자. 정해진 횟수가 끝나면 저절로 완료로 간다.

영상이 없거나 재생에 실패하면 **대체 안내 상자**가 나온다. 이 상태도 디자인해야 한다.

### 3-4. 완료 `#/complete` (주연 님 브랜치, 아직 `main` 전)
"루틴 완료" 제목 → 축하 영역(🎉 이모지, "수고했어요!", 오늘 N번째라는 문구) → **새로 받은 배지 카드**(원형 아이콘 자리, "새 배지" 라벨, 배지 이름, 문구. 카드가 차례로 등장하는 애니메이션) → 배지가 없으면 응원 문구 카드 → 버튼 "업무 복귀"(큰 주 버튼), "기록·배지 보기"(보조).
**B급 감성을 가장 크게 줄 곳이다.**

### 3-5. 통계 `#/stats` (주연 님 브랜치)
탭 2개("요약", "이번 주"). 요약: 오늘 완료 카드(완료/아직), 숫자 카드 2개(오늘, 지금까지), 배지 3열 그리드(획득·잠금·숨김 "???" 세 상태, 지금 13개). 이번 주: 평일 연속 기록 카드, 요일별·부위별·시간대별 횟수 막대, 빡침 명상 기록 카드.

### 3-6. 빡침 명상 `#/calm` (주연 님 브랜치)
제목 "잠깐 숨 돌리기" → **호흡 원**(들이쉬면 커지고 내쉬면 작아지는 애니메이션, 안에 "들이쉬기"/"내쉬기") + 안내 문구 + 진행 점(현재 3회) → "돌아가기". 마치면 완료 상태(아이콘, 메시지, 새 배지 카드 가능, "다시 하기"와 "돌아가기"). 자연 배경(진정 색)이 들어가는 화면이다.

### 3-7. 알림 배너 (모든 화면 위, 스트레칭 화면 제외)
알림 시각이 되면 화면 위에 고정되는 안내: "스트레칭 할 시간이에요 / 잠깐 몸을 풀고 올까요?" + "나중에", "시작" 버튼.

## 4. 화면 흐름

```
온보딩 ─▶ 메인 ─▶ 스트레칭 ─▶ 완료 ─▶ (업무 복귀) 메인
              ├─▶ 빡침 명상 ─▶ (돌아가기) 메인
              └─▶ 통계 ─▶ (돌아가기) 메인
알림 시각 ─▶ 배너/브라우저 알림 ─▶ 스트레칭(시작 단계부터)
```

## 5. 기술 제약 (디자인이 지켜야 한다)

- **React + Vite, 순수 CSS.** 스타일은 CSS 변수로 공통화한다. **새 라이브러리(CSS 프레임워크, 아이콘 패키지)와 외부 폰트 로딩은 팀 합의 없이 넣지 않는다.** 폰트는 Pretendard가 있으면 쓰고 없으면 시스템 한글 글꼴로 떨어지게 되어 있다.
- **기준 크기:** 모바일 375px. PC는 가운데 최대 480px 폭(`--app-width`).
- **터치:** 눌러야 하는 것의 최소 높이 48px(`--tap-size`).
- **글자 대비:** 글자와 배경은 4.5:1 이상. (현재 색은 계산으로 확인했다)
- **움직임:** `prefers-reduced-motion`에서는 줄이거나 끈다. 애니메이션은 호흡 원, 배지 등장, 버튼 눌림 정도로 제한한다.
- **소리가 없어도 이해**되어야 한다. 색만으로 상태를 구분하지 않는다. (예: 잠긴 배지는 모양도 달라야 한다)
- **이미지·영상:** 3D 캐릭터 영상은 `public/videos/<동작ID>.mp4`(예: `neck-01.mp4`), **16:9, 음소거 반복 재생**. 현재 6개(목 3, 어깨 3)만 있고 12개가 목표다. 영상이 없는 동작은 대체 안내가 나온다.
- 아이콘은 지금 **이모지**(🎉 ✅ 🌿 등)로 임시 표시 중이다. 배지 아이콘은 비어 있거나 이모지다.

## 6. 공통 부품과 클래스 이름

- **`Button`**: `variant` = `primary`(주 행동) / `soft`(보조) / `ghost`(약함) / `alert`(빡침·주의), `size` = `large` / `round`, `block`(가로 꽉). 클래스는 `btn btn--종류 btn--크기`.
- **`Screen`**: `.screen`, `.screen__header`, `.screen__title`, `.screen__body`
- **공통 클래스:** `.card`, `.muted`, `.stack`, `.field-row`, `.field`, `.input`, `.check`, `.error`, `.alert-banner`, `.dev-note`(임시 표시)
- **화면 전용 클래스 접두어:** `stretch-*`, `complete-*`, `stats-*`, `calm-*` (각 화면 CSS 파일 안)

## 7. 현재 디자인 토큰 (`src/index.css`)

변수 **이름은 바꾸지 않는다.** 다른 팀원의 화면 CSS가 이미 이 이름을 쓰고 있어서, 값만 바꿔야 화면이 깨지지 않는다. 새 변수는 추가해도 된다.

| 구분 | 변수 |
|---|---|
| 색 | `--color-bg`, `--color-surface`, `--color-primary`, `--color-primary-strong`, `--color-primary-soft`, `--color-calm`, `--color-calm-soft`, `--color-alert`, `--color-alert-soft`, `--color-text`, `--color-text-muted`, `--color-border`, `--color-page` |
| 강조·B급용 | `--color-accent`(라임), `--color-accent-strong`, `--color-on-accent`, `--color-sun`(노랑), `--color-sun-soft`, `--color-lavender`, `--color-outline` |
| 글자 | `--font-sans`, `--text-title`, `--text-large`, `--text-body`, `--text-small` |
| 여백 | `--space-1`(4px) ~ `--space-6`(32px) |
| 모양 | `--radius-md`, `--radius-lg`, `--radius-round`, `--shadow-card`, `--shadow-pop`, `--outline-width`, `--tap-size`, `--app-width` |

주의: `--color-primary`와 `--color-primary-strong`은 **글자색과 테두리로도 쓰인다.** 흰 배경에서 읽히는 진한 색이어야 한다. 강조 버튼의 바탕색은 `--color-accent`를 쓴다.

## 8. 파일과 담당 (수정 범위)

| 파일 | 담당 | 비고 |
|---|---|---|
| `src/index.css`, `src/App.css` | 공통 (김민지) | 토큰과 공통 부품. 변경은 한 PR로 짧게 |
| `src/pages/Main.jsx`, `Onboarding.jsx`, `src/components/*` | 김민지 | |
| `src/pages/Stretch.jsx`, `Stretch.css` | 김원규 | |
| `src/components/StretchVideo.jsx`, `.css` | 서진수 | |
| `src/pages/Complete.*`, `Stats.*`, `Calm.*` | 이주연 | |

- CSS만 바꾸는 것이 가장 안전하다. **마크업(JSX) 변경이 필요하면 어디를 어떻게 바꾸는지 목록으로** 달라. (담당자에게 확인해서 반영한다)
- 담당자가 아닌 사람의 파일은 담당자와 합의한 뒤에 바꾼다. (팀 규칙)

## 9. 납품 형식 (바로 적용할 수 있게)

1. **토큰 표:** 위 7번의 변수 이름 → 새 값. (새로 추가하는 변수는 따로 표시)
2. **화면별 CSS:** 파일 단위로 나눠서. (`index.css`, `App.css`, `Stretch.css`, `Complete.css`, `Stats.css`, `Calm.css`, `StretchVideo.css`) 기존 클래스 이름을 유지한다.
3. **마크업 변경 목록:** 추가하거나 바꿔야 하는 요소와 클래스. 없으면 "없음".
4. **상태별 화면:** 영상 없음, 알림 꺼짐, 배지 없음, 잠긴 배지, 호흡 단계, 완료 단계, 알림 배너, 모바일과 PC.
5. **새 에셋:** 파일 이름, 형식(SVG/PNG), 크기, 놓을 위치. (예: 배지 아이콘, 캐릭터 이미지)
6. **정적 시안:** 각 화면의 HTML + CSS 또는 이미지. 우리 클래스 이름을 쓰면 비교하기 쉽다.

## 10. 하지 않는 것

- 기능, 화면, 메뉴, 데이터를 추가하지 않는다. (하단 탭, 연속 일수 스트릭, 퀘스트 목록 등)
- 문구를 확정하지 않는다. (임시로 표시한다)
- 서비스 이름과 로고를 확정하지 않는다.
- 변수 이름과 클래스 이름을 바꾸지 않는다.
- 외부 라이브러리와 외부 폰트를 합의 없이 넣지 않는다.
