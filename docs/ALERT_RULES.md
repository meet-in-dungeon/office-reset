# 알림 설정과 발송 규칙

> 상태: 팀 전체에 전달됨 (2026-11-24, 팀장). 담당: 김민지.
> 이 문서는 "알림을 언제 보낼지"의 기준이다. 알림이 울리는 방식(앱 안 배너, 시스템 알림, 클릭 시 이동)은 [ARCHITECTURE.md](ARCHITECTURE.md)의 "알림 발송"을 본다.
> 2026-11-24 팀장 결정: 주기는 30분 / 1시간 / 2시간만 쓰고, 알림은 평일(월~금)에만 보낸다. 권한이 없어도 앱 안 배너는 보낸다.

## 1. 사용자 설정

| 항목 | 기본값 | 선택 범위 | 저장 키 (`settings`) |
|---|---|---|---|
| 출근 시각 | 09:00 | 시각 입력 | `workStart` |
| 퇴근 시각 | 18:00 | 시각 입력 | `workEnd` |
| 점심시간 | 12:00~13:00 | 시각 입력 (끌 수 있음) | `lunchEnabled`, `lunchStart`, `lunchEnd` |
| 알림 주기 | 1시간 | **30분 / 1시간 / 2시간** 중 선택 | `intervalMin` (30, 60, 120) |
| 알림 요일 | **평일(월~금) 고정** | 선택 기능 없음 | 저장하지 않는다. 주말에는 알림을 보내지 않는다 |
| 알림 ON/OFF | ON | 켜기/끄기 | `alertsEnabled` |

- 별도 설정이 없으면 1시간 주기를 쓴다.
- MVP에서는 **주기 직접 입력(예: 50분)과 요일 선택을 넣지 않는다.** 사용자 피드백을 보고 추가 여부를 정한다.

## 2. 알림 발송 규칙

1. 출근 시각을 기준으로 설정된 주기마다 알림을 보낸다.
2. 첫 알림은 출근 시각에서 주기가 지난 시점이다. (예: 09:00 출근, 1시간 → 10:00)
3. 점심시간과 근무시간 밖(퇴근 시각 포함)에는 보내지 않는다.
4. 점심시간 때문에 빠진 알림은 나중에 다시 보내지 않는다.
5. 오후 2시 이상 4시 미만에는 최소 1회 알림을 보내는 것을 원칙으로 한다.
6. 그 시간대에 정기 알림이 있으면 추가 알림은 보내지 않는다.
7. 정기 알림이 없으면 오후 3시에 추가 알림을 보낸다. 근무시간·점심시간 제외 규칙이 먼저다.
8. 추가 알림과 정기 알림 사이에는 최소 30분 간격을 둔다. 오후 3시가 조건에 맞지 않으면 오후 2~4시 안에서 가장 가까운 보낼 수 있는 시각으로 옮기고, 없으면 생략한다.
9. 사용자가 설정을 바꾸면 이후 알림 일정을 다시 계산한다.
10. **알림을 OFF로 하면 모든 알림(앱 안 배너와 시스템 알림)을 보내지 않는다.** 브라우저 알림 권한이 없으면 **시스템 알림만 생략하고, 앱 안 배너는 보낸다.** (팀장 결정 2026-11-24)
11. 주말(토·일)에는 알림을 보내지 않는다.

용어: **앱 안 배너**는 서비스 화면 위쪽에 뜨는 "스트레칭 할 시간이에요" 안내다. **시스템 알림**은 브라우저가 화면 구석에 띄우는 알림이고 사용자가 권한을 허용해야 뜬다.

## 3. 구현할 때 (단순하게)

- 5~8번(오후 2~4시 추가 알림)은 **기본 설정에서는 쓰이지 않는다.** 1시간·30분·2시간 주기는 기본 근무 시간에서 오후 2~4시에 정기 알림이 이미 있다. 점심이나 퇴근 시각을 오후 2~4시와 겹치게 바꿨을 때만 필요하므로 **구현 순서를 가장 뒤로 한다.**
- 8번에서 시각을 옮길 때는 5분 단위로 계산하고, 가장 가까운 시각이 둘이면 더 이른 시각을 쓴다. 오후 2시 이상 4시 **미만**이라 16:00 정각은 이 시간대에 포함하지 않는다.

## 4. 계산 예시

테스트 값으로 쓴다. (출근 09:00, 퇴근 18:00, 점심 12:00~13:00이 기본이고 다른 값은 표에 적었다)

| 설정 | 하루 알림 시각 | 추가 알림 |
|---|---|---|
| 기본 (1시간) | 10, 11, 13, 14, 15, 16, 17시 (7회) | 없음 |
| 30분 | 09:30부터 30분마다, 점심 제외, 17:30까지 (15회) | 없음 |
| 2시간 | 11, 13, 15, 17시 (4회) | 없음 (15시가 정기 알림) |
| 1시간, 점심 14:00~15:30 | 10, 11, 12, 13, **15:30**, 16, 17시 | 15:30 (15시는 점심시간, 가장 가까운 가능 시각, 16:00과 30분 간격) |

### 반영 작업

[WORK_UNITS.md](../WORK_UNITS.md) 4번 표의 "알림 규칙 반영" 한 줄이다. 순서는 아래와 같다.

1. 알림 주기 선택지를 30분 / 1시간 / 2시간으로 줄이고, 저장된 값을 보정한다.
2. 주말에는 알림이 없게 한다.
3. 시간이 남으면 5~8번(추가 알림)을 넣는다.

## 6. 주말과 하루 완성 배지

호흡 5회와 "하루 완성" 배지는 모두 **"하루의 마지막 루틴"**과 연결되어 있다. (`schedule.js`의 `isLastRoutine`, `records.js`의 배지 판정)

- 하루의 마지막 루틴 = 그날 **마지막 알림 시각 이후에 시작한 루틴**이다.
- 호흡은 마지막 루틴에만 붙고, "하루 완성" 배지는 호흡까지 끝낸 루틴(기록의 `breathCount`가 0보다 큼)에 지급된다.
- 주말에는 알림이 없어서 마지막 알림 시각이 없고, 그래서 마지막 루틴도 없다. 주말에 직접 스트레칭을 해도 호흡이 붙지 않고 **"하루 완성" 배지는 받을 수 없다.** ("첫 루틴" 배지와 횟수 기록은 그대로 쌓인다.)

평일만 알림을 보내기로 했으므로 주말에는 이 결과를 그대로 둔다. 주말에도 "하루 완성" 배지를 주고 싶어지면 그때 마지막 루틴 판정 방식을 따로 정한다.

## 7. 이 규칙이 다른 기능에 주는 영향

- **하루 알림 횟수 (`dailyRoutineCount`):** 주말에는 0이다. 메인 화면의 "다음 알림" 표시도 주말에는 비어 있어야 한다.
- **설정 화면:** 알림 주기 선택지가 줄어든다. 온보딩과 메인 설정(`WorkTimeSettings.jsx`)이 같이 바뀌며, 두 화면 모두 김민지 님 파일이다.
- **스트레칭 화면, 완료 화면:** 코드는 바뀌지 않는다. 주말에는 호흡이 안 나오고 하루 완성 배지가 없다는 점만 알고 있으면 된다.
