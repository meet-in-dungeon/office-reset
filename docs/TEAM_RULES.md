# 팀 협업 규칙

4명이 짧은 기간에 개발하므로 규칙은 최소한으로 둔다.

> AI(Claude Code, Codex)가 따르는 공통 규칙은 [AGENTS.md](../AGENTS.md)가 기준이다. 이 문서와 내용이 다르면 `AGENTS.md`를 따른다. 규칙을 바꿀 때는 팀원 합의 후 `AGENTS.md`를 먼저 고친다.

## 1. 기본 규칙

- 모든 팀원은 새 프로젝트를 만들지 않고 이 저장소 하나에서 개발한다.
- `main`에 직접 push 하지 않는다. 항상 PR로 합친다.
- PR은 팀원 1명 이상의 승인을 받은 뒤 병합한다.
- 브랜치는 `feature/`, `fix/`, `chore/` 중 하나로 시작한다.
- `main`은 언제나 `npm run build`가 성공하는 상태로 둔다.
- 병합이 끝난 브랜치는 지운다. (GitHub가 자동으로 지운다)

## 2. 담당 업무 나누기

- 기능 단위로 나눈다. 한 사람이 한 기능의 화면과 로직을 함께 맡는다.
- 담당표를 팀 단톡방 공지나 GitHub **Issues**에 둔다. 기능마다 Issue를 하나 만들고 담당자(Assignee)를 지정하면 누가 무엇을 하는지 보인다.
- 작업을 시작하기 전에 "이 기능 시작합니다"를 단톡방에 한 줄 남긴다.
- 내 담당이 아닌 파일은 고치기 전에 담당자에게 먼저 말한다.

## 3. 같은 파일을 고쳐야 할 때

- 같은 파일을 두 명이 동시에 고치면 충돌이 난다. 고치기 전에 단톡방에 "App.jsx 고칩니다"라고 알린다.
- 기능마다 파일을 따로 만든다. 예: `src/pages/Timer.jsx`, `src/pages/Breathing.jsx`
- 공통 파일 수정은 짧게 끝내고 바로 PR을 올려서 먼저 합친다. 오래 들고 있지 않는다.
- 하루에 한 번 이상 `main`을 내 브랜치에 합쳐 둔다. ([CONTRIBUTING.md](../CONTRIBUTING.md) 5번)

## 4. 공통 파일과 의존성 변경 규칙

공통 파일은 아래와 같다.

- `package.json`, `package-lock.json`
- `vite.config.js`, `index.html`
- `src/App.jsx`, `src/main.jsx`, `src/index.css`

규칙:

- 공통 파일은 기능 PR에 섞지 않고 `chore/` 브랜치로 따로 PR을 만든다.
- 새 라이브러리(`npm install 이름`)를 추가하기 전에 단톡방에 알린다. 정말 필요한지, 비슷한 것이 이미 있는지 확인한다.
- `package.json`을 바꿨다면 `package-lock.json`도 함께 커밋한다. 다른 팀원은 병합 후 `npm install`을 다시 실행한다.
- `package-lock.json`에서 충돌이 나면 직접 고치지 말고 팀장에게 말한다.
- 비밀 키, 비밀번호, 토큰은 코드나 문서에 적지 않는다. `.env`에만 적고 팀원에게는 따로 안전하게 전달한다.

## 5. AI(Claude 등)로 코드를 작성했을 때

AI가 쓴 코드도 내 코드다. PR을 올리기 전에 아래를 확인한다.

- [ ] 코드가 무슨 일을 하는지 읽고 설명할 수 있다.
- [ ] `npm run build`와 `npm run lint`가 통과한다.
- [ ] 브라우저에서 직접 눌러 보고 동작을 확인했다. (모바일 화면 크기 포함)
- [ ] 요청하지 않은 파일이 바뀌지 않았다. (`git status`, `git diff`로 확인)
- [ ] 새 라이브러리가 몰래 추가되지 않았다. (`package.json` 확인)
- [ ] 비밀 키나 개인정보가 코드에 들어가지 않았다.
- [ ] 남의 담당 파일이나 공통 파일을 마음대로 고치지 않았다.

AI에게 작업을 시킬 때는 "내 담당 파일 안에서만 작업해 줘"라고 범위를 알려 준다. AI가 만든 PR임을 숨길 필요는 없다. PR 템플릿의 AI 사용 칸에 적는다.

## 6. 리뷰 규칙

- 리뷰는 반나절 안에 한다. 오래 걸리면 단톡방에서 부른다.
- 큰 문제(빌드 실패, 비밀 키, 동작 안 함)가 아니면 취향 차이로 막지 않는다.
- 해커톤이므로 "완벽"보다 "동작하고 합칠 수 있는 상태"를 우선한다.

## 7. 노션 기록과 문제 공유

- 주요 진행 상황, 다른 팀원에게 영향을 주는 변경, 오류와 해결 과정은 노션 **실시간 전달 사항**에 기록한다. 채팅으로 말한 내용도 빠지지 않게 남긴다.
- 20~30분 이상 해결되지 않는 문제는 혼자 붙들지 않고 팀원에게 공유하고 도움을 요청한다.
- 개별 기능의 완성보다 전체 서비스의 완성을 우선한다. 내 기능이 막혀도 다른 기능이 돌아가게 둔다.
- 공통 협업 규칙(`AGENTS.md`, 이 문서)은 팀원 합의 후에만 바꾸고, 바꾼 뒤 팀원에게 알린다.
