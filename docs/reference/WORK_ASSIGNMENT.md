## 1. 김민지 — 서비스 기획·UI/UX·메인 기능
팀장 · 전체 서비스 기준 관리
**목표:** 사용자가 웹사이트에 접속하고, 알림을 설정한 뒤, 스트레칭 루틴을 시작할 수 있는 기본 화면과 기능을 완성한다.

| 구분 | 구체적으로 할 일 | 완료 기준 |
|---|---|---|
| 공통 개발 구조 | 화면 6개의 이동 방식, 공통 폴더 구조와 데이터 연결 규칙 정리 | 다른 팀원들이 자신의 기능을 개발할 수 있는 상태 |
| 디자인 기준 | 컬러, 폰트, 버튼, 여백, 모바일·PC 레이아웃 기준 정하기 | 모든 팀원이 같은 디자인 기준으로 제작 가능 |
| 온보딩 | 서비스 소개, 알림 설정, 이용 방법 및 주의사항 | 사용자가 처음 접속했을 때 서비스를 이해하고 설정 가능 |
| 메인 화면 | 타이머, 스트레칭 시작 버튼, 빡침 버튼, 기록·통계 진입 버튼 배치 | 각 버튼이 담당 화면으로 이동 |
| 업무 타이머 | 기본 60분, 사용자 주기 설정, 시작·종료 | 설정한 시간이 지나면 알림 실행 |
| 브라우저 알림 | 검증한 PoC를 실제 서비스에 연결 | Chrome에서 알림 표시 및 클릭 시 서비스 진입 |
| 사용자 설정 | 알림 주기, 알림 허용 상태, 소리 ON/OFF | 새로고침 후에도 설정 유지 |
| 전체 일정 관리 | 팀원별 작업·PR·막힌 점 확인 | 정해진 일정에 맞춰 통합 진행 |

**연결할 내용**
- 원규: 메인에서 스트레칭 시작 버튼을 누르면 루틴 화면이 열리게 연결
- 진수: 소리 ON/OFF 설정값을 영상·음성 기능에서도 사용
- 주연: 빡침 버튼을 명상 화면과 연결하고 통계·배지 화면으로 이동

**1차 완료 기준:** 웹에 접속해서 알림 주기를 설정하고, 타이머 종료 알림을 받은 뒤 스트레칭 루틴 화면으로 이동할 수 있다.
**2차 확장:** 온보딩 3페이지 디자인 완성, 상세 설정 화면, 화면 전반 디자인 개선.
**주의:** 민지가 모든 팀원의 코드를 대신 수정하는 것은 아니다. 공통 구조와 전체 일정은 관리하되 각 기능의 오류는 담당자가 직접 수정한다.

## 2. 김원규 — 스트레칭 콘텐츠·실행 루틴
**목표:** 사용자가 실제로 12개 스트레칭 동작을 따라 하고 마지막 호흡까지 완료할 수 있도록 콘텐츠와 실행 기능을 만든다.

| 구분 | 구체적으로 할 일 | 완료 기준 |
|---|---|---|
| 동작 선정 | 목·어깨·손목·허리 각 3개, 총 12개 최종 선정 | 실제 사무실에서 앉아서 할 수 있는 동작 12개 확정 |
| 동작별 정보 | 이름, 설명, 자세, 주의사항, 참고 출처 작성 | 웹에 바로 활용할 수 있는 데이터 완성 |
| 동작 ID | `neck-01` 등 12개 고유 번호 지정 | 진수 님이 해당 번호로 영상 제작 가능 |
| 스트레칭 화면 | 동작명, 설명, 영상, 카운트, 진행 상태 표시 | 사용자가 보고 동작을 따라 할 수 있음 |
| 동작 카운트 | 각 동작 5초 카운트 | 5초 뒤 자동으로 다음 동작으로 넘어가지 않음 |
| 다음 동작 | 사용자가 버튼을 누르면 이동 | 수동 전환 정상 작동 |
| 호흡 기능 | 스트레칭 종료 후 들이쉬기·내쉬기 5회 | 호흡 완료까지 진행 가능 |
| 완료 신호 | 전체 루틴 종료 사실을 기록 기능에 전달 | 주연 님의 배지 기능과 연결 가능 |
| 동작 검수 | 진수 님이 만든 영상과 원래 동작 비교 | 영상 움직임이 설명과 일치하며 위험한 자세가 없는지 확인 |

**정리할 스트레칭 데이터 항목:** 부위(목/어깨/손목/허리), 동작 ID(고정), 동작명(예: 목 옆으로 기울이기), 실행 방법, 주의사항(무리하거나 통증이 생길 때), 참고 출처(영상 링크, 도서 등), 영상 제작에 필요한 움직임 설명.
**중요:** 최종 동작 ID를 확정하면 진수 님에게 먼저 전달한다. 같은 동작을 같은 이름으로 관리해야 영상 연결이 가능하다.

**연결할 내용**
- 진수: 동작 데이터 및 참고 자료 전달 → 영상 제작 → 완성된 영상 검수
- 민지: 메인 화면에서 루틴으로 진입할 수 있도록 화면 연결
- 주연: 마지막 호흡을 완료하면 루틴 완료 정보를 전달

**1차 완료 기준:** 영상이 없어도 텍스트 안내를 보고 스트레칭을 순서대로 진행하고, 마지막 호흡까지 완료할 수 있다.
**2차 확장:** 전체 12개 영상 적용, 음성·카운트 안내 개선, 동작 주의사항 표시 보완.
우선 동작 1개로 화면 전체 흐름을 검증한 뒤 12개로 확장한다. 콘텐츠 조사와 화면 개발을 동시에 진행하므로, 모든 설명을 완성할 때까지 기다리지 않는다.

## 3. 서진수 — 3D 캐릭터 영상·소리·배포
**목표:** 사용자가 캐릭터의 움직임을 보고 스트레칭을 따라 할 수 있도록 영상을 제작하고, 웹에서 정상 재생되도록 구현한다.

| 구분 | 구체적으로 할 일 | 완료 기준 |
|---|---|---|
| 캐릭터 기준 | 사무복, 앉은 자세, 책상, 동일한 캐릭터 스타일 유지 | 모든 동작 영상의 캐릭터가 일관됨 |
| 영상 프롬프트 | 원규 님 자료를 기반으로 영상 제작용 프롬프트 작성 | 동작의 방향·순서·움직임이 표현됨 |
| 영상 제작 | 최종 동작 ID에 맞춰 3D 스트레칭 영상 제작 | 웹에 넣을 수 있는 영상 파일 확보 |
| 영상 파일 관리 | 예: `neck-01.mp4`, `shoulder-01.mp4` | 스트레칭 데이터와 파일명이 일치 |
| 영상 재생 기능 | 화면에서 해당 동작의 영상을 재생 | 모바일·PC Chrome에서 정상 작동 |
| 대체 화면 | 영상이 없거나 로딩에 실패할 때 텍스트 안내 표시 | 영상이 없어도 루틴 진행 가능 |
| 음성 안내 | 동작 안내와 카운트 음성 구현 | 소리 ON/OFF 설정 반영 |
| 배경음악 | 사용 권한을 확인한 BGM 적용 | 소리 끄기 및 재생 정상 동작 |
| 배포 | 최종 사이트를 외부 HTTPS 주소에서 열 수 있도록 설정 | 팀원과 발표 평가자가 링크로 접속 가능 |

**영상 제작 우선순위:** 1차 동작 1개 영상 제작 및 웹 재생 성공 → 2차 목·어깨·손목·허리 대표 영상 4개 → 3차 총 12개.
영상은 시간이 가장 많이 걸릴 수 있다(3시간에 3~4개 생성 가능했다는 검증 결과). 12개 완성을 기다렸다가 기능을 연결하면 안 된다.

**연결할 내용**
- 원규: 동작 정보·참고 영상 수령, 제작 영상 검수
- 민지: 소리 설정값과 공통 디자인 기준 확인
- 주연: 명상 화면에서 활용할 사운드 파일 협의

**1차 완료 기준:** 최소 1개의 3D 캐릭터 영상이 실제 루틴 화면에서 재생되고, 영상이 없는 동작은 대체 안내가 나온다. 이후 대표 영상 4개까지 확대한다.
**2차 확장:** 12개 영상 완성, 음성·BGM, 영상 용량 최적화.
배포 담당이지만 공통 설정 파일이나 배포 환경을 변경하기 전에는 팀과 합의한다. 영상 제작이 지연되면 배포 업무를 다른 팀원에게 재배정할 수 있다.

**배포 순서:** 최종 병합된 코드를 기준으로 배포 환경 설정 → Vercel·Netlify·GitHub Pages 등에 업로드 → HTTPS 주소 생성 → 배포된 사이트에서 영상·음성·알림 작동 확인 → 주소를 팀원에게 공유.

## 4. 이주연 — 배지·기록·통계·빡침 버튼
**목표:** 사용자의 스트레칭·명상 실천 결과를 저장하고 배지를 지급해, 다시 참여하고 싶게 만드는 보상 기능을 완성한다.

| 구분 | 구체적으로 할 일 | 완료 기준 |
|---|---|---|
| 배지 규칙 확정 | 조사한 배지 중 MVP 3종 우선 선정 | 각 배지의 획득 조건·이름·문구 확정 |
| 배지 데이터 | ID, 이름, 조건, 획득 여부 등 구조화 | 웹에서 배지 지급 판정 가능 |
| 실천 기록 | 루틴 완료 날짜와 횟수 저장 | 사용자의 실천 내역 기록 |
| 중복 방지 | 동일 루틴에 대한 중복 지급 방지 | 버튼을 여러 번 눌러도 배지 중복 지급 없음 |
| 하루 완성 | 해당 날짜의 루틴 완료 여부 계산 | 하루 완성 배지를 조건에 맞게 지급 |
| 완료 화면 | 루틴 종료 후 배지와 완료 안내 표시 | 새로 획득한 배지를 확인 가능 |
| 통계 화면 | 오늘 완료 여부, 총 완료 횟수, 획득 배지 | 새로고침 후에도 정보 유지 |
| 빡침 화면 | 자연 배경 및 호흡 안내, 돌아가기 버튼 | 메인에서 진입하고 다시 돌아갈 수 있음 |
| 명상 기록 | 빡침 해소 호흡 완료 기록 | 해당 배지 조건과 연결 가능 |
| 통합 테스트 | 전체 기능을 직접 테스트하고 문제 정리 | 화면별 오류·담당자 목록 작성 |

**우선 구현할 배지 3종**
| 배지 | 지급 조건 |
|---|---|
| 첫 루틴 | 최초 스트레칭·호흡 루틴 완료 |
| 하루 완성 | 해당 날짜에 루틴 완료 조건 충족 |
| 첫 빡침 해소 | 빡침 버튼에서 호흡 완료 |

배지 이름과 세부 조건은 주연 님의 기존 설계안을 활용하되 팀원들과 최종 확정한다.
중요: **같은 날 여러 번 스트레칭하면 횟수는 누적되지만 하루 완성 배지는 중복 지급하지 않는다.**

**연결할 내용**
- 원규: 루틴 완료 정보를 받으면 기록 저장 및 배지 지급
- 민지: 메인 화면의 빡침 버튼·통계 버튼과 연결
- 진수: 명상 화면에 들어갈 사운드 파일 협의

**1차 완료 기준:** 루틴을 완료하면 기록이 저장되고 배지가 표시되며, 새로고침 후에도 기록이 남는다. 명상 화면 역시 진입·호흡·종료가 가능해야 한다.
**2차 확장:** 브론즈·실버·골드 등급, 히든 배지, 연속 출석, 추가 통계, 명상 사운드.
통합 테스트 담당이라는 것은 다른 팀원의 코드를 대신 수정한다는 뜻이 아니다. 오류를 확인하고 담당자에게 전달하며 수정 결과를 재검증하는 역할이다.

**통합 테스트 순서**
1. 웹사이트 접속 → 온보딩과 알림 설정
2. 업무 타이머 시작 → 다른 탭에서 작업
3. 알림 수신 → 스트레칭 화면 진입
4. 스트레칭 → 호흡 → 루틴 완료
5. 배지 지급 → 기록 저장 → 통계 확인
6. 빡침 버튼 → 명상 화면 → 메인 복귀

## 5. 공통 협업 규칙
1. 네 사람 모두 `meet-in-dungeon/office-reset` **하나의 저장소**에서 작업한다.
2. 각자 **개별 브랜치**에서 담당 기능을 개발한다.
3. 다른 팀원의 담당 파일을 허락 없이 수정하지 않는다.
4. 기능 완성 후 Pull Request(PR)를 생성한다.
5. 팀원 1명의 리뷰·승인을 받고 `main`에 병합한다.
6. 공통 파일 수정이나 새로운 라이브러리 설치가 필요하면 먼저 공유한다.
7. AI가 완료했다고 해도 직접 화면에서 작동 여부를 테스트한다.

## 6. 개발 순서
1. 민지가 GitHub에 공통 화면 구조와 개발 기준을 먼저 준비한다.
2. 그동안 원규는 동작 12개와 ID를 확정해 진수에게 전달한다. 진수는 영상 제작을 진행하고, 주연은 MVP 배지 3종의 이름·획득 조건·문구를 최종 정리한다.
3. 공통 구조가 준비되면 각자 저장소를 받아 개인 브랜치에서 담당 기능 개발을 시작한다.
4. 기능을 완료하면 PR을 올리고 팀원 리뷰를 받은 뒤 main에 합친다.
