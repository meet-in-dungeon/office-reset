# 최종 확정 사항 (DECISIONS)

> 기준일: 2026-11-24. 노션 회의록(11/19, 11/23)과 업무 분배 문서를 바탕으로 정리한 **초안**이다.
> 팀장이 확인하기 전에는 "초안"으로 본다. 회의 녹음 내용은 아직 반영되지 않았다.
> 표시 규칙: **확정** = 회의·업무 분배에서 정해짐 / **미확정** = 아직 정해지지 않음. AI는 미확정 항목을 임의로 정하지 않고 사용자에게 묻는다.

## 1. 프로젝트 개요 (확정)
- 팀 "던만": 김민지(팀장), 김원규, 서진수, 이주연
- 목표: 직장인이 업무 중 알림을 받고, 짧은 스트레칭과 호흡을 실천한 뒤, 배지와 기록으로 꾸준한 회복 습관을 만드는 웹 서비스
- 타깃: 사무실에서 일하는 30~50대 직장인. 앉은 자세, 업무 중 사용
- 형태: 웹. 모바일 중심, PC에서도 좁지 않게 (무신사 방식 참고)
- 발표용 앱이다. 상용화가 아니라 "끝까지 동작하는 데모 한 흐름"이 중요하다.
- 기술: React + Vite, 4인이 GitHub 하나(`meet-in-dungeon/office-reset`)에서 PR로 공동 개발
- 일정: 11/24 기능 개발·중간 점검, 11/25 최종 merge·발표 준비, **11/26(목) 10:00 제출 마감**, 14:30 온라인 발표
- 1차 목표: 각자 모든 기능을 완성하는 것이 아니라 **알림 → 스트레칭 → (하루 마지막 루틴이면 호흡) → 배지 지급·기록**으로 이어지는 전체 흐름이 실제로 작동하게 만든다.

## 2. 사용자 흐름 (확정)
1. 최초 접속: 온보딩(알림 설정 포함)
2. 메인 화면: 타이머, 스트레칭 시작, 빡침 버튼, 기록·통계 진입
3. 정해진 알림 시각이 되면 → 브라우저 알림 → 알림 클릭 시 서비스 진입 (알림 시각은 출근·퇴근·점심시간·주기 설정으로 계산)
4. 스트레칭: 동작마다 5초 카운트 → 동작이 끝나면 **멈추고**, 사용자가 **버튼을 눌러** 다음 동작으로 (자동 전환 없음)
5. **하루의 마지막 루틴에서만** 스트레칭이 끝난 뒤 **호흡 들이쉬기·내쉬기 5회**를 한다. 일반 루틴은 호흡 없이 끝나고, 호흡이 필요하면 빡침 버튼으로 간다. (김민지, 11/24)
6. 루틴 완료 → 기록 저장 → 배지 지급 → 완료 화면
7. 통계 화면에서 기록 확인
8. 빡침 버튼 → 명상 화면(자연 배경 + 호흡 안내) → 메인 복귀

## 3. 콘텐츠 (확정)
- 부위: 목, 어깨, 손목, 허리. 부위별 3개씩 **총 12개** 동작. 앉아서 하는 동작만.
- 동작 ID는 `neck-01`처럼 고정한다. 영상 파일명도 같은 ID를 쓴다. (예: `neck-01.mp4`)
- 동작 시간: 동작마다 영상 한 바퀴와 동작 이름 음성이 끝난 뒤 5초 카운트 (음성은 동작 이름만 읽고 카운트 숫자는 읽지 않는다. 소리가 꺼져 있으면 영상 한 바퀴 뒤 시작)
- 주의 문구: "통증이 느껴지면 중단하세요. 전문가와 상의하세요. 천천히 충분히 호흡하면서 움직여 주세요."
- 영상: 3D 캐릭터(사무복, 앉은 자세, 책상 있음)로 확정. 영상이 없으면 텍스트 안내로 대체하고 루틴은 계속 진행된다.
- 영상 제작량: 동작 1개 → 대표 4개(부위별 1개) → 12개 순서. 12개 완성을 기다리지 않고 기능을 먼저 연결한다.
- 참고 출처: 전문가 유튜브, 김원규 님 보유 도서(『실전 기능해부학』)
- **동작 선정(확정):** 12개 전체에서 서로 다른 3개를 고르고, 12개가 한 번씩 나오기 전에는 같은 동작이 다시 나오지 않는다. 김원규 님이 구현했고 `lastPart`는 쓰지 않는다.
- **한 번의 루틴 = 스트레칭 동작 3개** (팀 합의, 11/24). 개수는 `ROUTINE_MOVE_COUNT` 한 곳에서 바꾼다. 호흡 5회는 매 루틴이 아니라 **하루의 마지막 루틴에만** 붙는다.
- 동작 "이전" 버튼은 없고 **"다음" 버튼만** 둔다. (김민지 결정, 11/24)
- **호흡 1회의 길이(확정, 11/24):** 들이쉬기 4초 + 내쉬기 4초. 5회면 약 40초.
- **넘기기의 정의(확정, 11/24):** 5초 카운트가 끝나기 전에 "다음"을 누른 동작을 넘긴 동작으로 센다. 그 수가 `skippedMoves`이며 "스킵은 사치" 배지 계산에 쓴다.

확정 동작 12개 (김원규 님 최종 정리, 노션 실시간 전달 사항):
| ID | 동작 | ID | 동작 |
|---|---|---|---|
| neck-01 | 목 늘이기 | wrist-02 | 손목 뒤쪽 늘이기 |
| neck-02 | 대각선 목 늘이기 | wrist-03 | 주먹 쥐었다 펴기 |
| neck-03 | 턱 당기기 | wrist-04 | 손목 가볍게 돌리기 |
| shoulder-01 | 가슴 펴기 | waist-01 | 앉아서 허리 비틀기 |
| shoulder-02 | 팔 가슴 앞으로 당기기 | waist-02 | 옆구리 늘이기 |
| shoulder-03 | 깍지 끼고 등 밀기 | waist-03 | 등 둥글게 말기와 펴기 |

손목은 11/24에 손목 앞쪽 늘이기(`wrist-01`)를 영상 제작이 어려워 예비로 빼고 손목 가볍게 돌리기(`wrist-04`)를 넣었다. (김원규, 팀장 확인)

예비 동작 4개(`neck-04`, `shoulder-04`, `wrist-01`, `waist-04`)는 2차 확장용이며 지금은 만들지 않는다. 좌우 대칭 동작은 한쪽만 영상으로 만들고 앱에서 좌우 반전하므로, 안내 음성에 "오른쪽·왼쪽" 단어를 쓰지 않는다.

## 4. 기능 범위

### 1차 필수 (확정)
- 공통 뼈대(화면 이동, 폴더 구조, 데이터 연결 규칙, 디자인 기준) — 김민지
- 메인 화면, 업무 타이머(기본 60분, 사용자 변경), 브라우저 알림, 기본 설정(알림 주기·허용 상태·소리 ON/OFF, 새로고침 후 유지) — 김민지
- 스트레칭 12개 동작 데이터, 실행 화면, 5초 카운트, 수동 다음 버튼, 하루 마지막 루틴의 호흡 5회, 루틴 완료 신호 — 김원규
- 대표 영상 4개, 웹 재생, 영상 대체 화면, 기본 음성, 소리 ON/OFF 반영, 배포 — 서진수
- 배지 1~3종, 기록 저장, 완료 화면, 기본 명상(빡침) 화면, 통계 화면, 통합 테스트 — 이주연

### 2차 (1차 완료 후)
- 온보딩 3페이지 완성·세부 디자인·추가 설정 (민지)
- 영상 12개 전체, BGM, 영상 최적화, 음성·카운트 안내 개선 (진수·원규)
- 등급 배지, 히든 배지, 연속 출석, 상세 통계, 명상 사운드 (주연)
- 회원가입·로그인 (MVP는 브라우저 저장)

### 제외 (이번에 만들지 않음)
- 웹캠 자세 인식·실시간 피드백(향후 확장 후보), 개인 맞춤 추천, 주간 랭킹, 상황별(서서·누워서) 스트레칭, 일시정지·재시작, 휴식 건너뛰기·연기, 즉시 루틴 시작

## 4-1. 알림 시간 설정과 마지막 루틴 (확정, 11/24)
- 사용자가 **출근 시각, 퇴근 시각, 점심시간, 알림 주기**(기본 1시간)를 설정한다. 기본값은 09:00~18:00, 점심 12:00~13:00이다.
- 알림은 출근 시각에서 주기만큼씩 더한 **정해진 시각**에 울린다. 점심시간과 퇴근 시각에는 울리지 않는다. 기본값이면 10, 11, 13, 14, 15, 16, 17시로 **하루 7회**다.
- **마지막 알림(기본 17:00)이 하루의 마지막 루틴이고, 이 루틴에만 호흡 5회가 붙는다.** 판정은 `isLastRoutine()`(시각 기준)이고, 하루 알림 횟수는 `settings.dailyRoutineCount`(읽기 전용)로 읽는다. 자세한 사용법은 [docs/ARCHITECTURE.md](../ARCHITECTURE.md) 참고.

## 5. 배지·기록 (일부 확정)
- 배지는 **이주연 님의 "배지 획득 규칙 설계안"(노션 실시간 전달 사항)을 따른다.** 초안이며 12개(일반 10 + 히든 2) + 예약 1개(빡침 해소)다. 일반 배지는 브론즈·실버·골드 등급이 있다. 배지 디자인도 이주연 님이 맡는다.
  - 일반: 첫 리셋, 출근 도장, 리셋 장인, 하루 완성, 평일 개근상, 스트레칭 도감, 스킵은 사치, 모닝 리셋, 식곤증 격파, 광속 리셋
  - 히든: 몸관리 끝판왕(같은 날 루틴 7번, 확정 11/25·PR #17), 불금에도 스트레칭 퐈이어(금요일 17시 이후)
- 업무 분배의 1차 우선 구현은 3종(첫 루틴 = 첫 리셋 / 하루 완성 / 첫 빡침 해소)이다.
- **하루 완성 = 그날 마지막 루틴을 호흡까지 완료하면 지급** (이주연 님 동의, 11/24). 설계안의 "하루 루틴 3회"는 이 조건으로 바꾼다. 기록의 `breathCount`가 0보다 크면 마지막 루틴으로 본다. 같은 날 여러 번 해도 하루 완성은 하루에 한 번만 나간다.
- 1차 배지 3종 이름(이주연 님 정리): 첫 루틴 = **"첫 스트레칭 성공!"**, 하루 완성 = **"나를 위한 하루"**, 첫 빡침 해소 = **"인간 공기청정기"**
- 배지 상태·루틴 기록은 브라우저(`localStorage`)에 저장하고, 배지는 기록 전체로 매번 다시 계산한다. 기록 형식은 [docs/ARCHITECTURE.md](../ARCHITECTURE.md) 참고.
- 통계 화면: 오늘 완료 여부, 총 완료 횟수, 획득 배지. 새로고침 후에도 유지.
- 저장: **브라우저 기반**(같은 브라우저에서 유지). 서버 저장은 하지 않는다.

## 9. 자료 간 충돌 정리
| 항목 | 이전 자료 | 현재 기준 |
|---|---|---|
| 호흡 | 회의록 MVP 표: 호흡 가이드 "제외" | **필수.** 단, **하루의 마지막 루틴에만 5회**. "5초"는 동작 하나의 카운트 시간이고 호흡은 "5회"다. 업무 분배 문서·`PRD.md`·원규 님 문서는 "매 루틴 끝"으로 읽힐 수 있어 이 문서를 따른다 |
| 동작 전환 | 회의 중 3가지 방안 논의 | **수동 전환**(버튼) |
| 소리·BGM | 회의록: 음성·BGM 필수 | 소리 ON/OFF·기본 음성은 1차, **BGM은 2차** |
| 담당 | `WORK_UNITS.md`, `PRD.md`: A~D 역할 미배정 | **이름별로 배정됨** (위 6번) |
