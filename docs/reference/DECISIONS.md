# 최종 확정 사항 (DECISIONS)

> 기준일: 2026-11-24. 노션 회의록(11/19, 11/23)과 업무 분배 문서를 바탕으로 정리한 **초안**이다.
> 팀장이 확인하기 전에는 "초안"으로 본다. 회의 녹음 내용은 아직 반영되지 않았다.
> 표시 규칙: **확정** = 회의·업무 분배에서 정해짐 / **미확정** = 아직 정해지지 않음. AI는 미확정 항목을 임의로 정하지 않고 사용자에게 묻는다.

## 1. 프로젝트 개요 (확정)
- 팀 "던만": 김민지(팀장), 김원규, 서진수, 이주연
- 목표: 직장인이 업무 중 알림을 받고, 짧은 스트레칭과 호흡을 실천한 뒤, 배지와 기록으로 꾸준한 회복 습관을 만드는 웹 서비스
- 타깃: 사무실에서 일하는 30~50대 직장인. 앉은 자세, 업무 중 사용
- 형태: 웹. 모바일 중심, PC에서도 좁지 않게 (무신사 방식 참고)
- 발표용 앱이다. 상용화가 아니라 "끝까지 동작하는 데모 한 흐름"이 중요하다.
- 기술: React + Vite, 4인이 GitHub 하나(`meet-in-dungeon/office-reset`)에서 PR로 공동 개발
- 일정: 11/24 기능 개발·중간 점검, 11/25 최종 merge·발표 준비, **11/26(목) 10:00 제출 마감**, 14:30 온라인 발표
- 1차 목표: 각자 모든 기능을 완성하는 것이 아니라 **알림 → 스트레칭 → 호흡 → 배지 지급·기록**으로 이어지는 전체 흐름이 실제로 작동하게 만든다.

## 2. 사용자 흐름 (확정)
1. 최초 접속: 온보딩(알림 설정 포함)
2. 메인 화면: 타이머, 스트레칭 시작, 빡침 버튼, 기록·통계 진입
3. 업무 타이머 종료 → 브라우저 알림 → 알림 클릭 시 서비스 진입
4. 스트레칭: 동작마다 5초 카운트 → 동작이 끝나면 **멈추고**, 사용자가 **버튼을 눌러** 다음 동작으로 (자동 전환 없음)
5. 스트레칭이 끝나면 마지막에 **호흡 들이쉬기·내쉬기 5회**
6. 루틴 완료 → 기록 저장 → 배지 지급 → 완료 화면
7. 통계 화면에서 기록 확인
8. 빡침 버튼 → 명상 화면(자연 배경 + 호흡 안내) → 메인 복귀

## 3. 콘텐츠 (확정)
- 부위: 목, 어깨, 손목, 허리. 부위별 3개씩 **총 12개** 동작. 앉아서 하는 동작만.
- 동작 ID는 `neck-01`처럼 고정한다. 영상 파일명도 같은 ID를 쓴다. (예: `neck-01.mp4`)
- 동작 시간: 동작당 5초 카운트 (나레이션 "고개 돌리세요" 후 5~1)
- 주의 문구: "통증이 느껴지면 중단하세요. 전문가와 상의하세요. 천천히 충분히 호흡하면서 움직여 주세요."
- 영상: 3D 캐릭터(사무복, 앉은 자세, 책상 있음)로 확정. 영상이 없으면 텍스트 안내로 대체하고 루틴은 계속 진행된다.
- 영상 제작량: 동작 1개 → 대표 4개(부위별 1개) → 12개 순서. 12개 완성을 기다리지 않고 기능을 먼저 연결한다.
- 참고 출처: 전문가 유튜브, 김원규 님 보유 도서(『실전 기능해부학』)
- **한 번의 루틴 = 스트레칭 동작 3개 + 호흡 5회** (팀 합의, 11/24). 개수는 `ROUTINE_MOVE_COUNT` 한 곳에서 바꾼다.
- 동작 "이전" 버튼은 없고 **"다음" 버튼만** 둔다. (김민지 결정, 11/24)

확정 동작 12개 (김원규 님 최종 정리, 노션 실시간 전달 사항):
| ID | 동작 | ID | 동작 |
|---|---|---|---|
| neck-01 | 목 옆 늘이기 | wrist-01 | 손목 앞쪽 늘이기 |
| neck-02 | 대각선 목 늘이기 | wrist-02 | 손목 뒤쪽 늘이기 |
| neck-03 | 턱 당기기 | wrist-03 | 주먹 쥐었다 펴기 |
| shoulder-01 | 가슴 펴기 | waist-01 | 앉아서 허리 비틀기 |
| shoulder-02 | 팔 가슴 앞으로 당기기 | waist-02 | 옆구리 늘이기 |
| shoulder-03 | 깍지 끼고 등 밀기 | waist-03 | 등 둥글게 말기와 펴기 |

예비 동작 4개(`neck-04`, `shoulder-04`, `wrist-04`, `waist-04`)는 2차 확장용이며 지금은 만들지 않는다. 좌우 대칭 동작은 한쪽만 영상으로 만들고 앱에서 좌우 반전하므로, 안내 음성에 "오른쪽·왼쪽" 단어를 쓰지 않는다.

## 4. 기능 범위

### 1차 필수 (확정)
- 공통 뼈대(화면 이동, 폴더 구조, 데이터 연결 규칙, 디자인 기준) — 김민지
- 메인 화면, 업무 타이머(기본 60분, 사용자 변경), 브라우저 알림, 기본 설정(알림 주기·허용 상태·소리 ON/OFF, 새로고침 후 유지) — 김민지
- 스트레칭 12개 동작 데이터, 실행 화면, 5초 카운트, 수동 다음 버튼, 호흡 5회, 루틴 완료 신호 — 김원규
- 대표 영상 4개, 웹 재생, 영상 대체 화면, 기본 음성, 소리 ON/OFF 반영, 배포 — 서진수
- 배지 1~3종, 기록 저장, 완료 화면, 기본 명상(빡침) 화면, 통계 화면, 통합 테스트 — 이주연

### 2차 (1차 완료 후)
- 온보딩 3페이지 완성·세부 디자인·추가 설정 (민지)
- 영상 12개 전체, BGM, 영상 최적화, 음성·카운트 안내 개선 (진수·원규)
- 등급 배지, 히든 배지, 연속 출석, 상세 통계, 명상 사운드 (주연)
- 회원가입·로그인 (MVP는 브라우저 저장)

### 제외 (이번에 만들지 않음)
- 웹캠 자세 인식·실시간 피드백(향후 확장 후보), 개인 맞춤 추천, 주간 랭킹, 상황별(서서·누워서) 스트레칭, 일시정지·재시작, 휴식 건너뛰기·연기, 즉시 루틴 시작

## 5. 배지·기록 (일부 확정)
- 배지는 **이주연 님의 "배지 획득 규칙 설계안"(노션 실시간 전달 사항)을 따른다.** 초안이며 12개(일반 10 + 히든 2) + 예약 1개(빡침 해소)다. 일반 배지는 브론즈·실버·골드 등급이 있다. 배지 디자인도 이주연 님이 맡는다.
  - 일반: 첫 리셋, 출근 도장, 리셋 장인, 하루 완성, 평일 개근상, 스트레칭 도감, 스킵은 사치, 모닝 리셋, 식곤증 격파, 광속 리셋
  - 히든: 몸관리 끝판왕(하루 8회 이상), 불금에도 스트레칭 퐈이어(금요일 17시 이후)
- 업무 분배의 1차 우선 구현은 3종(첫 루틴 = 첫 리셋 / 하루 완성 / 첫 빡침 해소)이다.
- **하루 완성 = 설계안 기준 "하루에 루틴 3회"** (+ 빡침 1회는 미정). 같은 날 여러 번 스트레칭하면 횟수는 누적되지만 하루 완성 배지는 같은 날 중복 지급하지 않는다. 버튼을 여러 번 눌러도 배지는 중복 지급되지 않는다.
- 배지 상태·루틴 기록은 브라우저(`localStorage`)에 저장하고, 배지는 기록 전체로 매번 다시 계산한다. 기록 형식은 [docs/ARCHITECTURE.md](../ARCHITECTURE.md) 참고.
- 통계 화면: 오늘 완료 여부, 총 완료 횟수, 획득 배지. 새로고침 후에도 유지.
- 저장: **브라우저 기반**(같은 브라우저에서 유지). 서버 저장은 하지 않는다.

## 8. 미확정 항목 (임의로 정하지 말고 팀에 확인)
| 항목 | 메모 |
|---|---|
| **동작 선정 방식** | 루틴의 동작 수는 3개로 확정. 어떤 3개인지는 미정: 원규 님 문서는 "한 부위의 3개(직전 부위 연속 금지)", 주연 님 문서는 "12개 풀에서 랜덤 3개" |
| 루틴 인정 기준 | 호흡 5회까지 끝나야 인정하는지, 동작 3개 완료만 보는지 (원규 님·주연 님 문서가 다름) |
| 호흡 1회의 길이 | 루틴 전체 시간(가볍게 vs 길게)을 좌우한다 |
| 알림 후 큰 "시작" 버튼 첫 단계 | 새로 나온 제안(11/24). 원규 님이 의견 수렴 중. 알림 클릭 때만 보여줄지도 함께 정한다 |
| "넘기기"의 정의 | 버튼이 "다음"뿐이라 5초가 끝나기 전에 누르면 넘기기로 볼지. "스킵은 사치" 배지 계산에 필요 |
| 하루 완성 배지의 빡침 포함 여부 | 설계안 결정 필요 ②. 빡침 버튼 세부 기획 확정 후 결정 |
| 빡침 명상 완료 조건·배지 연결 | 진입·종료 방식, 호흡 몇 회인지 |
| 배지 이름·문구·히든 배지 이름 | 주연 님 설계안(초안)의 "결정 필요" ①~⑤를 팀이 확정 |
| 온보딩에서 받을 정보 | 3페이지 구성(프롤로그·알람 설정·사용 가이드·주의사항)만 정해짐 |
| 서비스명, 디자인 기준 | 후보 아이디어: "3분 리셋" 등 (확정 아님) |
| 배포 플랫폼 | Vercel, Netlify, GitHub Pages 중 (진수 님) |
| 음성·BGM 파일 출처·사용 권한 | 권한 확인한 것만 저장소에 올린다 |
| 과정 요구사항(EXAONE API, 스트리밍 등) | 필수 여부 확인 필요. MVP 기능에는 AI가 없다 |
| 시연(test) 모드 | 평가자가 빠르게 체험하도록 하는 모드. 검토 후보 |
